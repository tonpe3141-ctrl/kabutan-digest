# マーケットダッシュボード

日本株を **寄り前 / 前場 / 大引** の3つの視点で振り返る、スマートフォン最適化ダッシュボード。
GitHub Actions が1日3回データを取得し、GitHub Pages の固定 URL を更新する。

**公開URL（Pages 有効化後）**
<https://tonpe3141-ctrl.github.io/kabutan-digest/>

---

## 1. 更新の流れと時刻

時計は **Claude Routine**、収集は **GitHub Actions**、表示は **GitHub Pages**。

| 時刻（JST） | 画面 | 何が起きるか |
|---|---|---|
| 平日 07:10 | **寄り前** | Routine が合図を push → Actions が米国市場・為替金利・前日引け後の開示・株探と報道各社・公的機関のニュースを収集 → Routine が見立てを書いて通知。個別株の日足が前営業日まで届いていなければ取り直し、今日有効の注文を寄りの前に出す |
| 平日 11:40 | **前場** | 同上。前場の指数・33業種・ランキング・場中開示・株探昼刊の見出し |
| 平日 16:45 | **大引** | 同上。加えて発掘台帳を1日ぶん進め、Routine が候補の理由づけとテーマ辞書の追記を書く。当日の引けで翌営業日の注文を出す（CNBC の日足に当日の分が入るのは夜なので、引け後のクォートで当日の日足を補う） |
| 金 17:00 | **週報** | Routine が5営業日の履歴と台帳から週次の総括を書いて通知（市況の「推移」に出る） |

GitHub の cron はベストエフォートで、実測では毎日2〜7時間遅れていた（前場の実行が16〜17時に
発火し、前場タブが一度も埋まらなかった）。そのため cron に時計を任せるのをやめ、Routine が
`docs/data/trigger/{slot}.txt` を push した **push イベント**で Actions を起動する（数秒で始まる）。
cron は保険として1区分1本だけ残してある。保険の cron は `--insurance` 付きで走り、その日の区分が既に
Routine の合図で作られていれば何もしない（遅れて夜に発火し、取り直しで東証33業種などが欠けた実測があるため）。
同じ区分を取り直したときに取れなかった区画は、前回の値を引き継ぐ。

Routine の手順書は `dashboard/AI_ANALYSIS_TASK.md`。トークンを減らすため、Routine は latest.json を丸ごと読まず `tools/ai_brief.py` の要約（約85%減）を読み、
書いた中身を `tools/ai_write.py` で差し込む（出典は参照番号で書き、URL はこの道具が戻す。DESIGN.md 23章）。Routine の push は `claude/routine-{slot}` ブランチに
置き換えられることも、main に直接届くこともある（2026-09-28 は main に直接届いた）。ブランチに置き換えられたときは、
`tools/verify_ai_merge.py` が許可したファイルだけの変更なら `.github/workflows/merge-ai-branch.yml` が main に自動マージする
（ブランチは残す。スロットごとに1本の下書き PR が「Routine の記録」として開いたままになる）。収集のワークフローは、
push で合図（`docs/data/trigger/*.txt`）が変わっていれば、どちらの経路でもその区分を走らせる。

### Routine の配線（いま動いているもの）

モデルは **Claude Sonnet 5**（2026-09-18 に Fable 5.1 から変更）。

| 定時トリガー | 起こすセッション | push 先ブランチ |
|---|---|---|
| マーケット 寄り前（07:10 JST, 月〜金） | `session_01MGYzqbEWTG4BRE55JP7MM8` | `claude/routine-preopen` |
| マーケット 前場（11:40 JST, 月〜金） | `session_01KqCZXqPJVQtAswrty8axDm` | `claude/routine-zenba` |
| マーケット 大引（16:45 JST, 月〜金） | `session_01SJx5Y9mqpaPanmP1GpgoRu` | `claude/routine-taibike` |
| マーケット 週報（17:00 JST, 金） | `session_01VED72RQiofPhUMy5zWFF4A` | `claude/routine-weekly` |

リポジトリを接続していないセッションからは push できない（実測）ので、セッションは
リポジトリを接続して作り、トリガーはそのセッションを起こす形にしてある。
セッションを作り直すときは、claude.ai の Routine 作成画面でリポジトリ `tonpe3141-ctrl/kabutan-digest` を
接続し、上の時刻と `dashboard/AI_ANALYSIS_TASK.md` の表にあるプロンプトで作れば同じ動きになる。
時刻の意味: 大引が 16:45 なのは、株探の「日経平均 大引け」記事が 16:33 頃に出るため。

### モデルを変えるとき

**Routine の設定画面でモデルだけ変えても効かない。** この 4 本はセッションに固定されており
（`persistent_session_id`）、モデルはトリガーではなく**セッション側**が持っているため。
トリガーのモデル欄が効くのは「毎回新しいセッションを作る」タイプの Routine だけ。

手順は次の 3 つ。**セッションとトリガーを両方張り替える**のがポイント。

1. 新しいモデルでセッションを 4 本作る。リポジトリ `tonpe3141-ctrl/kabutan-digest`（main）を接続し、
   push 先を `claude/routine-{slot}`（既存と同じ名前）にする
2. 既存のトリガー 4 本を消し、同じ時刻・同じプロンプトで、新しいセッションに紐づけて作り直す
3. 古いセッションをアーカイブし、この表のセッション ID を差し替える

チャット側（この会話）のモデルは `/model` で変えられるが、Routine には影響しない。別々の設定。

モデルの選び方: 手順書（`dashboard/AI_ANALYSIS_TASK.md`）が細かく決まっているので、
判断の重い作業は残っていない。日々の分析は Sonnet 5 で足りる。
分析の解釈をもっと深くしたいときだけ上位モデルを検討する。

## 2. データはどこから取っているか

株探（kabutan.jp）は GitHub Actions のランナーからだと
`405 Human Verification` を返して取得できない（stooq・Yahoo Finance 米国版も同様に
クラウドIPを拒否する）。実測のうえ、クラウドから確実に取れる3つに組み替えている。

| 区分 | ソース | 取得できるもの |
|---|---|---|
| 相場データ | CNBC クォートAPI | 米指数（S&P500・NASDAQ・ダウ・SOX・ラッセル・VIX）、日経平均、TOPIX、JPX日経400、米セクターETF 12本、ドル円、米2年/10年債、WTI、金 |
| 日本株の物色 | Yahoo!ファイナンス | 売買代金上位・上昇率・下落率ランキング |
| 決算・開示 | TDnet 適時開示 | 決算短信・業績予想の修正・配当予想の修正・自己株式取得など（一次情報、ETF等は除外） |
| 株探の見出し | Google ニュース RSS（site:kabutan.jp） | 昼刊・夕刊・大引け・ストップ高安・レーティング日報などの見出しと時刻（本文なし） |
| 株探の記事本文 | Yahoo!ファイナンス ニュース一覧（株探ニュース配信分） | 大引け記事・マーケット日報・**東証33業種の騰落**・PTS・増資売り出しなど |
| 公的機関の発表 | 日本銀行・財務省・日本取引所グループ・FRB の公式 RSS | 表題と時刻（一次情報）。日銀は総裁会見・決定会合・短観など、財務省は大臣会見・為替介入・利付国債入札などに絞る |
| 報道の見出し | Google ニュース RSS（ロイター・ブルームバーグ・日本経済新聞・時事通信）、NHK 経済 RSS | 市況・為替・金利・決算・関税の見出しと時刻（本文なし）。**配信元ドメインで照合**し、転載・プレスリリース・株価ページ・スポーツは落とす |
| 他社の記事本文 | Yahoo!ファイナンス ニュース一覧（時事通信・トレーダーズ・ウェブ・ウエルスアドバイザー配信分） | 〔NY株式〕〔NY外為〕などの市況記事、注目銘柄の解説。時事の有料記事は冒頭のみ |
| 海外の報道 | CNBC RSS（Markets・Economy・Earnings） | 英語の見出しと要約 |
| 短信・マクロの材料 | Yahoo!ファイナンス ニュース一覧（トレーダーズ・ウェブ配信分） | 経済指標の結果（予想つき）・発表予定・要人発言の表題と、イベントスケジュール・FF金利織り込み度・主な経済指標・マーケットダイジェストの本文 |
| 決算の材料 | TDnet の開示の PDF、Yahoo!ファイナンスの銘柄ごとのニュース欄 | 会社の説明（修正の理由・経営成績の概況・業績予想の説明。一次情報）、株探の【決算速報】（数字の要約と「よく比較される銘柄」）、東証33業種、時事通信・ウエルスアドバイザーの個別の見出し。決算発表予定は株探の「来週の決算発表予定」「サプライズ決算」の本文から |
| 追加ランキング | Yahoo!ファイナンス | 年初来高値更新・出来高急増（ETF・REIT は除外） |
| 日足（相場温度計・マクロ環境） | CNBC 日足API（`ts-api.cnbc.com`） | 日経・TOPIX・日経VI・日本2/10/30年債・S&P500・SOX・VIX・ドル円・米2/10/30年債・WTI・金・銅 を約3年、個別株（225採用・ウォッチリスト・テーマ辞書・台帳など約400銘柄）を130営業日。分割調整済み |
| 業績（相場温度計） | 日経公式 PER 表 | 日経平均の指数ベースPER（当月分しか載らないので毎日積み上げる）→ 予想EPS |

情報源は **信頼性を絶対条件** に選んでいる（一次情報／通信社・全国紙・公共放送／市況の事実報道を業とする
金融情報ベンダー）。コラム中心の媒体・まとめサイト・SNS は使わない。許可リストは `dashboard/config.py` の
`PRESS_FEEDS` と `PRESS_YAHOO_PROVIDERS`。

取れないもの:

- **株探の記事本文のうち Yahoo に配信されないもの**（話題株ピックアップの本文など。見出しは取れる）
- **ロイター・ブルームバーグ・日経の記事本文**（見出しのみ。本文は各社サイト）
- **日経平均先物のクォート**（CNBC のクォートAPIに無いため、想定オープンはモデル推計に一本化。日足APIには `@NK.1` がある）

Claude Routine のセッションからは GitHub と api.anthropic.com 以外に出られないので、
収集は必ず Actions が行う。

データが取れなくなったら Actions の **データ源の疎通診断** を手動実行すると、
相手サイトの遮断なのかこちらのパーサの不具合なのかが切り分けられる。

## 3. このダッシュボードが普通と違うところ

数値を並べるだけでなく、**差分と含意**を出すことに寄せている。

- **想定オープン** — 日経平均先物が取れればそれを、取れなければ公開係数モデル
  （`0.55×S&P500 + 0.25×SOX + 0.35×ドル円`）で寄り付きのギャップを推計する。
  どちらを使ったかは画面に必ず明示する。
- **米国 → 日本セクターの連想** — 米セクターETF・米10年金利・ドル円・原油の前日変化から、
  今日どの日本の業種に追い風／向かい風が吹くかを並べる。根拠となった指標も一緒に表示する。
- **答え合わせ** — 朝の想定と実際の前場を突き合わせる。当てにいくためではなく、
  「今日は外部環境で説明できる動きか、日本市場固有の材料があるか」を切り分けるため。
- **前場 → 後場の変化** — 前場終値のスナップショットを保存しているので、
  後場に買われたのか売られたのかを市況の大引で出せる。
- **上げの中身** — 日経平均（値がさ株の影響大）と TOPIX（時価総額加重・全銘柄）の
  ズレを見る。日経だけが伸びていれば「一部の値がさ株が押し上げただけで
  市場全体は見た目ほど強くない」と指摘する。
- **適時開示の分類** — TDnet の表題を機械的に分類し、業績予想の修正・決算短信を
  先に、自己株式取得や月次は折りたたんで出す。翌日の寄りで飛ぶ銘柄が拾いやすい。
  ETF・ETN・投資信託の開示（毎日大量に出る収益分配金の告知）は除外する。
- **相場の見立て** — 市況の各区分の先頭（要点の中に畳んで）に、指標を組み合わせた分析文を出す。
  外部の生成AIは使わない。同じ数字からは必ず同じ文章が出るので、あとで検証できる。
  指数どうしのズレ、米2年債と10年債の動き方の差、売買代金上位の顔ぶれといった
  「対比」から含意を出す構成にしている（`dashboard/commentary.py`）。
- **マクロ環境** — 米日の金利（2・10・30年）・ドル円・原油・金・銅の水準と前日／5日／20日の変化、1年のレンジの中の位置、
  取れている約3年での最高・最低、米国の長短差と日米の金利差を1枚の表にし、報道・公的機関・株探の見出しを
  マクロの話題（日銀・FRB・為替・原油・地政学・通商・財政・指標・中国・需給）ごとに「何媒体が報じたか」で数える。
  経済指標の結果・要人発言・今夜のイベント予定・FF金利の織り込みも同じカードで読める（`dashboard/macro.py`）。
  見立ては Routine が記事と数字を突き合わせて書く（`ai_macro`）。無いときは数字だけで組み立てた文章。
- **決算から読む** — 決算・業績修正の開示ごとに、会社の説明（TDnet の PDF）・株探の決算速報・類似銘柄（株探の比較銘柄 →
  テーマ辞書の同じテーマ → 日経225の同じ業種）の値動き・20日の騰落・次の決算予定・最近の決算の向きを機械が集め、
  直近20営業日に読んだ開示の上向き／下向きを業種・テーマごとに数える（`dashboard/earnings.py`）。
  何が分かったか・業界の風向き・類似銘柄への連想・次に確かめることは Routine が書く（`ai_earnings`）。
  類似銘柄は連想の材料で、買う候補ではない（買う候補は売買タブの2つのルールだけ）。
- **資金の向き先の入れ替わり** — 売買代金上位の顔ぶれを前営業日と比較し、
  新規ランクイン・順位急上昇・連続ランクイン日数を出す。
- **テーマ別の資金の向き** — 銘柄→テーマ辞書（`docs/data/themes.json`）で売買代金・上昇率・
  年初来高値更新の顔ぶれを束ね、テーマごとの出現数・平均騰落・連続日数・初動を出す。
  辞書に無い銘柄は Routine が記事を読んでテーマを付け、辞書が育つ。判定そのものは辞書で決定的に行う。
- **発掘台帳** — 入口は機械（3〜6日の連続ランクイン、新規流入、順位急上昇、上方修正・増配、
  決算で商い、上昇率×売買代金、年初来高値×商い、修正後の資金流入、テーマ初動）、理由づけは Routine、
  検証は d1/d5/d20 の追跡とシグナル別の成績（`docs/data/ledger.json`）。当てるためではなく、
  自分の見方が効いているかを確かめるための仕組み。
- **時間軸** — 業種の 5日／20日の累積と「続伸／反発／押し目／続落」の読み、日経の推移。
- **相場温度計（逆張りガード）** — 業績（予想EPS・修正の方向）・モメンタム・過熱感（RSI・25日線乖離・騰落レシオ）・
  原油・金利・為替・米国株・センチメント（VIX・日経VI・見出しの論調）の8軸を −2〜+2 で採点し、0〜100 の温度にする。
  全部追い風＝天井圏に多い形、全部向かい風＝大底圏に多い形、という逆張りの読みを、
  **過去3年の日足で温度計を当て直した成績（温度帯ごとの20日・60日後）と並べて**出す。
  業種は「押し目」「過熱」など、銘柄は「高値掴み注意」、開示への反応から「好材料／悪材料出尽くし」を機械的に判定し、
  大引で記録して5日・20日後の成績を追う（`dashboard/thermo.py`、`docs/data/thermo.json`）。設計と採点は `DESIGN.md` 9章。
  注文の条件には使わない（押し目買いは温度で絞るとかえって成績が落ちた。13章）。
- **短期の押し目買い（売買タブの中心）** — 買う候補を出すのはこれと下の中期の押し目の2つのルールだけ（1銘柄に1つの計画）。上昇トレンド（終値 > 200日線、50日線 > 200日線）の
  銘柄（20日平均の売買代金30億円以上・株価300円以上。23章）が 2日RSI 10 未満まで短く押した日の引けで、**翌営業日だけ有効の買いの指値**（終値 − 0.5ATR）、損切りの逆指値（約定値 − 3ATR）、
  毎朝置き直す**売りの指値**（直近4日の終値の平均。ただし買値 +0.2% より下には置かない＝含み損のうちは戻りを待つ）、10営業日の期限を出す。**業種の中での位置**（テーマ辞書の主テーマ、
  無ければ日経の業種の20日騰落を、自分を除いた中央値と比べる）で押しの形を分け、業種ぐるみの押し・出遅れの押しを先に、
  業種の上げに沿った業種並みの押しは見送る（1回の平均がマイナス。14章）。25日線からの下離れ＋業種より遅れている分が大きい順に1日5銘柄まで
  （同じ業種は2銘柄まで）。業種タブの「押し目の業種」に、業種ぐるみで下げた／上げた業種と、その中で下げが大きい・
  遅れている銘柄を、このルールでの位置と一緒に並べる。2022-10〜2026-09 の四本値（約380銘柄）で、場中の安値での損切り・窓開け・売買コストまで再現して
  選んだ（前半で決め、後半でも勝率69%。売り指値の下限を付けて前半 86%・後半 87%。以前の型は同じ条件で39〜54%）。検証は毎日やり直し、アプリが出した注文の実績も
  同じ規則で測る（`dashboard/swing.py`、`docs/data/swing_track.json`）。設計と検証は `DESIGN.md` 13〜16章。
- **株数と口座の伸び** — 1件の注文は資金の10%ずつ（金額をそろえる）。保有中に使っていない資金の範囲で上から置く。損切り幅から株数を
  決める（1回の損＝資金の1%）より、同じ張り具合で口座が速く増えた（4年で年率 +20% → +31%、月でプラスだった割合 68% → 79%）。
  口座の成績は **本番どおりの置き方**（引けで決めて翌日だけ有効、約定しなければ資金はその日遊ぶ）で毎日測り直して出す
  （置いた注文の約定は38%で、以前の「約定した注文の中から選ぶ」数え方は楽観的だった）。買いは IFD、翌朝からは売りの指値と損切りを OCO で置く。
  設計と検証は `DESIGN.md` 16章。
- **中期の押し目（大きなトレンドの中の1〜3か月の調整）** — 1年で強い銘柄（12か月の強さが上位1/3、200日線が上向き）が60日高値から
  20〜59営業日・−10% 以上調整している中で、短く押した日（2日RSI 10 未満）に同じ指値を置き、損切りは調整の安値 − 1ATR、売りの指値は置かず
  60営業日目の引けで売る。中期の保有は6銘柄まで、短期より先に置く。中期の形の押しは短期の注文には出さない。4年の検証で、
  調整の条件なしで強い銘柄の押しを買うより1回の平均が良く（前半 +5.4% 対 +3.0%・後半 +6.2% 対 +3.6%）、短期と合わせた口座は年率
  +18% → +30%（前半）・+41% → +61%（後半）。ただし勝率は3割前後、最大の目減りは深くなり、改善の多くは大きく伸びた少数の銘柄から。
  売買タブの「もうすぐ」に調整中の銘柄と押し待ちの価格も出す。設計と検証は `DESIGN.md` 21章。
- **候補に添える決算の材料**（`dashboard/picks.py`）— 候補ごとに自社の決算・同業や類似銘柄の決算の向き・次の決算日（保有中にまたぐか）を添え、
  Routine が「なぜ押したか」を1行で書く（`ai_picks`）。候補・並び順は変えない（決算の向きが効くかは注文の記録で確かめる）。
  売買タブの「決算の連想」に、決算が上向きで上昇トレンド・売買代金の条件を満たす銘柄を、買い候補までの近さで並べる。`DESIGN.md` 23章。
- **業種の強弱（業種タブ）** — 押し目買いと同じ業種の束ね方（テーマ辞書の主テーマ、無ければ日経の業種）で、市場との差（60日・120日）・
  業種の200日線からの位置・50日線より上にある銘柄の割合の順位を平均した「強さ」と、10日の「勢い」で4象限に分ける。
  4年の検証で、強さの上位1/5 は次の20日に市場を平均 +1.2%／+2.2%（前半／後半）上回り、下位1/5 は −0.4%／−1.1%。
  弱い業種の戻り（改善）は次の20日も負けがち。短い期間の強さや日経の業種の束ね方では効かなかった。注文の条件には使わない
  （口座の再現が後半で良くならなかった）。設計と検証は `DESIGN.md` 17章。
- **発掘は監視に** — 台帳（機械が見つけた銘柄）とウォッチリストは、見つけた日に買わず「あと何％下げたら注文対象か」を並べる
  監視の一覧に統合した。

## 5. ウォッチリストの入れ替え

銘柄は頻繁に入れ替える前提で、3通りの方法を用意している。

### A. ダッシュボード上で編集（推奨・最速）
売買タブの監視の **ウォッチを編集** → コードを追加／削除 → **保存して反映**。1銘柄ずつなら、銘柄シートの **☆ ウォッチに入れる** でも登録できる（トークンがあれば同じくリポジトリに書く）。

初回だけ **連携設定** から GitHub トークンを登録すると、保存がそのまま
`docs/data/watchlist.json` へのコミットになり、株価の再取得まで自動で走る（数分で反映）。
この再取得（`--slot watchlist`）は表示中の各区分のウォッチリストだけを差し替え、区分や履歴は作り直さない
（休場日・時間外に保存しても、前営業日の画面は消えない）。

- 推奨トークン: **Fine-grained personal access token**
- Repository access: `kabutan-digest` のみ
- Permissions: **Contents: Read and write** だけ（他は不要）
- トークンはその端末のブラウザ内（localStorage）にのみ保存され、リポジトリには入らない

> トークンを登録しない場合、編集内容はその端末にだけ保存される。サーバ側は銘柄を知らないので、
> 自動更新を待っても開示・ランキングの突き合わせには載らない（監視に「この端末だけ」と出る）。
> 株価は温度計の日足など手元のデータで分かる範囲だけ表示する。

### B. チャットから頼む
Claude に「ウォッチリストに 6501 を追加して」と言えば `docs/data/watchlist.json` を
更新してプッシュする。トークン登録は不要。

### C. ファイルを直接編集
`docs/data/watchlist.json` の `codes` を書き換えてコミットする。
このファイルへの push は自動的にデータ再取得のトリガーになる。

```json
{ "codes": ["7203", "8035", "6501"] }
```

### 設計上の約束

- **収集は必ず完走する** — どこかが取れなくても他の区画は出す。`http.py` は例外を投げず
  `None` を返し、`build.py` は区画ごとに握り潰す。
- **パーサは位置で読む** — ランキング表はセル内テキストが連結されるため、
  「数値らしさ」ではなく列位置で読む。実測した構造は `tests/` に固定してある。
- **履歴は差分と時間軸のために残す** — 前日比較・業種の累積・テーマの連続日数に必要な列だけを保存し、120日で自動削除する。

## 8. 注意

CNBC・Yahoo!ファイナンス・TDnet・Google ニュースの公開ページを自動取得したもので、
正確性・即時性は保証されない。CNBC の日本株指数は遅延がある。
特に「想定オープン」と「セクター連想」は将来の株価の予測ではなく、
**外部環境の並び順を機械的に整理したもの**として扱うこと。投資判断は自己責任で。
