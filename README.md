# マーケットダッシュボード

日本株を **寄り前 / 前場 / 大引** の3つの視点で振り返る、スマートフォン最適化ダッシュボード。
GitHub Actions が1日3回データを取得し、GitHub Pages の固定 URL を更新する。

**公開URL（Pages 有効化後）**
<https://tonpe3141-ctrl.github.io/kabutan-digest/>

---

## 1. 更新の流れと時刻

時計は **Claude Routine**、収集は **GitHub Actions**、表示は **GitHub Pages**。

| 時刻（JST） | 画面 | 何が起きるか |
|---|---|---|
| 平日 07:10 | **寄り前** | Routine が合図を push → Actions が米国市場・為替金利・前日引け後の開示・株探の見出しを収集 → Routine が見立てを書いて通知 |
| 平日 11:40 | **前場** | 同上。前場の指数・33業種・ランキング・場中開示・株探昼刊の見出し |
| 平日 16:45 | **大引** | 同上。加えて発掘台帳を1日ぶん進め、Routine が候補の理由づけとテーマ辞書の追記を書く |
| 金 17:00 | **週報** | Routine が5営業日の履歴と台帳から週次の総括を書いて通知（履歴画面の先頭に出る） |

GitHub の cron はベストエフォートで、実測では毎日2〜7時間遅れていた（前場の実行が16〜17時に
発火し、前場タブが一度も埋まらなかった）。そのため cron に時計を任せるのをやめ、Routine が
`docs/data/trigger/{slot}.txt` を push した **push イベント**で Actions を起動する（数秒で始まる）。
cron は保険として1区分1本だけ残してある。

Routine の手順書は `dashboard/AI_ANALYSIS_TASK.md`。Routine の push は `claude/*` ブランチに置き換えられ、
`tools/verify_ai_merge.py` が許可したファイルだけの変更なら `.github/workflows/merge-ai-branch.yml` が
main に自動マージする。

## 2. データはどこから取っているか

株探（kabutan.jp）は GitHub Actions のランナーからだと
`405 Human Verification` を返して取得できない（stooq・Yahoo Finance 米国版も同様に
クラウドIPを拒否する）。実測のうえ、クラウドから確実に取れる3つに組み替えている。

| 区分 | ソース | 取得できるもの |
|---|---|---|
| 相場データ | CNBC クォートAPI | 米指数（S&P500・NASDAQ・ダウ・SOX・ラッセル・VIX）、日経平均、TOPIX、JPX日経400、米セクターETF 12本、ドル円、米2年/10年債、WTI、金 |
| 日本株の物色 | Yahoo!ファイナンス | 売買代金上位・上昇率・下落率ランキング |
| 決算・開示 | TDnet 適時開示 | 決算短信・業績予想の修正・配当予想の修正・自己株式取得など（一次情報、ETF等は除外） |
| 株探の見出し | Google ニュース RSS（site:kabutan.jp） | 昼刊・夕刊・大引け・ストップ高安・レーティング日報などの見出しと時刻（本文なし） |
| 株探の記事本文 | Yahoo!ファイナンス ニュース一覧（株探ニュース配信分） | 大引け記事・マーケット日報・**東証33業種の騰落**・PTS・増資売り出しなど |
| 追加ランキング | Yahoo!ファイナンス | 年初来高値更新・出来高急増（ETF・REIT は除外） |

取れないもの:

- **株探の記事本文のうち Yahoo に配信されないもの**（話題株ピックアップの本文など。見出しは取れる）
- **日経平均先物**（CNBC に無いため、想定オープンはモデル推計に一本化）

Claude Routine のセッションからは GitHub と api.anthropic.com 以外に出られないので、
収集は必ず Actions が行う。

データが取れなくなったら Actions の **データ源の疎通診断** を手動実行すると、
相手サイトの遮断なのかこちらのパーサの不具合なのかが切り分けられる。

## 3. このダッシュボードが普通と違うところ

数値を並べるだけでなく、**差分と含意**を出すことに寄せている。

- **想定オープン** — 日経平均先物が取れればそれを、取れなければ公開係数モデル
  （`0.55×S&P500 + 0.25×SOX + 0.35×ドル円`）で寄り付きのギャップを推計する。
  どちらを使ったかは画面に必ず明示する。
- **米国 → 日本セクターの連想** — 米セクターETF・米10年金利・ドル円・原油の前日変化から、
  今日どの日本の業種に追い風／向かい風が吹くかを並べる。根拠となった指標も一緒に表示する。
- **答え合わせ** — 朝の想定と実際の前場を突き合わせる。当てにいくためではなく、
  「今日は外部環境で説明できる動きか、日本市場固有の材料があるか」を切り分けるため。
- **前場 → 後場の変化** — 前場終値のスナップショットを保存しているので、
  後場に買われたのか売られたのかを大引タブで出せる。
- **上げの中身** — 日経平均（値がさ株の影響大）と TOPIX（時価総額加重・全銘柄）の
  ズレを見る。日経だけが伸びていれば「一部の値がさ株が押し上げただけで
  市場全体は見た目ほど強くない」と指摘する。
- **適時開示の分類** — TDnet の表題を機械的に分類し、業績予想の修正・決算短信を
  先に、自己株式取得や月次は折りたたんで出す。翌日の寄りで飛ぶ銘柄が拾いやすい。
  ETF・ETN・投資信託の開示（毎日大量に出る収益分配金の告知）は除外する。
- **相場の見立て** — 各タブの先頭に、指標を組み合わせた分析文を出す。
  外部の生成AIは使わない。同じ数字からは必ず同じ文章が出るので、あとで検証できる。
  指数どうしのズレ、米2年債と10年債の動き方の差、売買代金上位の顔ぶれといった
  「対比」から含意を出す構成にしている（`dashboard/commentary.py`）。
- **資金の向き先の入れ替わり** — 売買代金上位の顔ぶれを前営業日と比較し、
  新規ランクイン・順位急上昇・連続ランクイン日数を出す。
- **テーマ別の資金の向き** — 銘柄→テーマ辞書（`docs/data/themes.json`）で売買代金・上昇率・
  年初来高値更新の顔ぶれを束ね、テーマごとの出現数・平均騰落・連続日数・初動を出す。
  辞書に無い銘柄は Routine が記事を読んでテーマを付け、辞書が育つ。判定そのものは辞書で決定的に行う。
- **発掘台帳** — 入口は機械（3〜6日の連続ランクイン、新規流入、順位急上昇、上方修正・増配、
  決算で商い、上昇率×売買代金、年初来高値×商い、修正後の資金流入、テーマ初動）、理由づけは Routine、
  検証は d1/d5/d20 の追跡とシグナル別の成績（`docs/data/ledger.json`）。当てるためではなく、
  自分の見方が効いているかを確かめるための仕組み。
- **時間軸** — 業種の 5日／20日の累積と「続伸／反発／押し目／続落」の読み、日経の推移。

## 3.5 画面構成（スマートフォン向けアプリ）

下端のナビで4つの画面を切り替える。設計の経緯と採点は `DESIGN.md` の 7 章を参照。

| 画面 | 内容 |
|---|---|
| **今日** | 寄り前／前場／大引を切り替えて読む。先頭に3行サマリー、次に見立て、その下に詳細。長い表は畳んであり「すべて見る」で開く。上端のチップで各セクションへ跳べる |
| **発掘** | 連続ランクイン・新規流入・上方修正／増配・決算で商い・修正後の資金流入といった機械的なシグナルで候補を並べる。`docs/data/ledger.json` があればそちらを優先 |
| **履歴** | 営業日ごとの日経終値・騰落・売買代金上位・想定と実際・上方修正の件数。タップで当日の中身を開く |
| **銘柄** | ウォッチリストと、コード／社名での横断検索 |

時間帯ボタンには予定時刻ではなく実際の更新時刻を出し、取れていなければ「未取得」と表示する。
ホーム画面に追加すると全画面で開き、圏外でも最後に見た状態が出る（サービスワーカー）。

## 4. 初回セットアップ（2ステップ）

このダッシュボードは公開市場データしか使わないため、**Secrets の登録は不要**。

1. **リポジトリを public にする**
   Settings → General → 最下部 Danger Zone → *Change repository visibility* → Public
2. **GitHub Pages を有効化する**
   Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / フォルダ: `/docs` → Save

数分後に `https://tonpe3141-ctrl.github.io/kabutan-digest/` が開く。
初回はデータが空なので、Actions タブから **マーケットダッシュボード更新** を
`workflow_dispatch` で手動実行するとすぐ中身が入る。

> スマホでは Safari/Chrome の共有メニューから「ホーム画面に追加」しておくと、
> アプリのように全画面で開ける（`manifest.webmanifest` 対応済み）。

## 5. ウォッチリストの入れ替え

銘柄は頻繁に入れ替える前提で、3通りの方法を用意している。

### A. ダッシュボード上で編集（推奨・最速）
画面の「ウォッチリスト」カード右上の **編集** → コードを追加／削除 → **保存して反映**。

初回だけ **連携設定** から GitHub トークンを登録すると、保存がそのまま
`docs/data/watchlist.json` へのコミットになり、株価の再取得まで自動で走る（数分で反映）。

- 推奨トークン: **Fine-grained personal access token**
- Repository access: `kabutan-digest` のみ
- Permissions: **Contents: Read and write** だけ（他は不要）
- トークンはその端末のブラウザ内（localStorage）にのみ保存され、リポジトリには入らない

> トークンを登録しない場合でも編集内容はその端末に保存される。ただしサーバ側は
> 銘柄を知らないため、株価は「次回更新後に反映」と表示される。

### B. チャットから頼む
Claude に「ウォッチリストに 6501 を追加して」と言えば `docs/data/watchlist.json` を
更新してプッシュする。トークン登録は不要。

### C. ファイルを直接編集
`docs/data/watchlist.json` の `codes` を書き換えてコミットする。
このファイルへの push は自動的にデータ再取得のトリガーになる。

```json
{ "codes": ["7203", "8035", "6501"] }
```

## 6. ローカル実行

```bash
pip install -r requirements.txt

python tests/test_parsers.py                    # パーサの回帰テスト（ネット不要）

python -m dashboard.build --slot preopen        # 寄り前
python -m dashboard.build --slot zenba          # 前場
python -m dashboard.build --slot taibike        # 大引
python -m dashboard.build --slot auto           # 現在時刻から判定
python -m dashboard.build --slot zenba --date 20260904   # 日付指定

python tools/probe.py                           # データ源の疎通診断

# ダッシュボードをローカルで開く（docs/data/latest.json をそのまま読む）
python -m http.server 8000 --directory docs     # → http://localhost:8000
```

> 自宅の回線からなら株探にもアクセスできるので、ローカル実行では取得できる。
> 自動更新はクラウド上で動くため、上記3ソースだけを使う。

  analyze.py         想定オープン／リスク環境／セクター連想／上げの中身／差分

  data/history/      日次スナップショット（前日比較・連続ランクイン・履歴画面に使用）
  data/history/index.json  履歴の一覧（履歴画面が読む）
  data/watchlist.json
  data/themes.json   銘柄→テーマ辞書（Routine が育てる）

### 設計上の約束

- **収集は必ず完走する** — どこかが取れなくても他の区画は出す。`http.py` は例外を投げず
  `None` を返し、`build.py` は区画ごとに握り潰す。
- **パーサは位置で読む** — ランキング表はセル内テキストが連結されるため、
  「数値らしさ」ではなく列位置で読む。実測した構造は `tests/` に固定してある。
- **履歴は差分と時間軸のために残す** — 前日比較・業種の累積・テーマの連続日数に必要な列だけを保存し、120日で自動削除する。

## 8. 注意

CNBC・Yahoo!ファイナンス・TDnet・Google ニュースの公開ページを自動取得したもので、
正確性・即時性は保証されない。CNBC の日本株指数は遅延がある。
特に「想定オープン」と「セクター連想」は将来の株価の予測ではなく、
**外部環境の並び順を機械的に整理したもの**として扱うこと。投資判断は自己責任で。
